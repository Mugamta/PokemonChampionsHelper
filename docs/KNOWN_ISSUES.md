## 계산에 반영 안 된 것

- 설치기는 교체로 들어올 때 자동 반영 (스텔스록·압정뿌리기·독압정·끈적끈적네트). 두꺼운부츠는 챔피언스 도구 목록에 없어서 미반영.
- 특성/도구 중 BATTLE_MECHANICS 에 없는 것. 변덕쟁이는 결과가 무작위라 안내만 하고 랭크는 직접 입력,
  부가효과도 확률만 표시하고 실제로 걸렸는지는 "이번 턴 상태이상 발생"으로 입력 (게임 결과를 봐야 알 수 있음)
- 라이벌의식: 상대 성별을 선출 화면에서 고르지 않았으면 보정 없음 (0.75~1.25 범위로 보여 주지 않음)
- 더블: 도우미·프렌드가드 외 아군 효과 없음. ①②③ 분석은 선택한 1:1 조합(focus) 기준
- 애널라이즈 판정은 공격 대상과의 행동 순서만 본다 (더블에서 "필드 전체 중 마지막" 여부는 판단 안 함)
- 도구 소모 자동 판정은 반감열매·풍선·기합의띠만. 그 외(탁쳐서떨구기 등)는 필드 패널에서 수동
- 배틀 화면의 "이번 턴 생긴 상태이상"은 각 진영의 분석 대상(focus) 포켓몬에게 적용
- 실전 KO 확률(대타 뒤): 단타는 KO 확률 없이 대타가 깨질 확률만, 연속기는 한 번 써서 대타를 깨고 본체까지 쓰러뜨릴 확률 (여러 번 사용은 계산 안 함).
  변덕레이저는 대타가 깨질 확률 생략
- 챔피언스에는 구애머리띠·구애안경이 없다 (도구 목록 기준). 구애스카프만 계산
- 상대 스피드 구간: 스피드 하락 성격(겁쟁이 등 −)은 다루지 않음, 우선도가 다른 기술끼리의 선후공은 관찰로 쓰지 않음.
  상대 특성은 입력값 기준이라 특성을 모르면 (예: 쓱쓱 여부) 잘못 좁힐 수 있음 → 추정 초기화 버튼
- 상대 배분 추정: 데미지 입력이 틀리면 "맞는 배분 없음"이 될 수 있음 (추정 초기화로 지움). 랭크·상태를 잘못 입력해도 같은 문제.
  상대 도구를 확정하지 않았으면 데미지 도구 후보 중 하나로 가정 (선출 화면 도구는 추측이라 고정하지 않음, 특성 보정은 입력한 특성만)
- 배틀의 상대 배분 범위: 공격 쪽은 공격·특공 범위를 따로 좁혀 양 끝을 쓴다 (내구처럼 조합으로 묶지 않음). 공격 관측의 도구 후보가 여럿이면
  범위는 모든 후보를 합친 것이고 계산은 확정 도구만(추측 도구는 "○○이면" 줄). 상대 HP % ↔ 실수치 환산은 HP 범위의 가운데라 실제와 다를 수 있음.
  선후공을 모를 때 적용을 막는 건 분석 대상 칸끼리만 (더블의 나머지 짝은 범위 가운데 스피드)
- 성능표: 특성은 결정력을 가장 높이는 것으로 고르고 조건부 특성(근성·모래의힘·선파워 등)은 조건 미충족으로 계산. 도구 없음

## 환경

- `nuxt build` 시 Vuetify 4 CSS `@layer` 관련 esbuild 경고 3건 — Vuetify 쪽 문제, 동작 영향 없음.
- npm 10.9 에서 vitest 설치 시 peer 해석 버그(`edgesOut`)가 있어 `--legacy-peer-deps` 로 설치했다. 일반 `npm install`/`npm ci` 는 정상.
- Windows Git Bash 에서 `NUXT_APP_BASE_URL=/PokemonChampionsHelper/` 로 빌드할 때 `MSYS_NO_PATHCONV=1` 필요.
- 예전 URL(`/partySelect`, `/entrySelect`, `/singleEntrySelect`, `/doubleEntrySelect`, `/singleBattle`)은 라우터 리다이렉트로 새 경로로 보낸다.
  빌드 시 예전 경로도 SPA 셸 HTML 로 생성되므로 GitHub Pages 직접 접속도 동작한다 (base 경로 포함 빌드로 확인).
- 예전 버전에서 저장한 내 파티(localStorage `pokemon-champions-my-party`)는 첫 로드 시 새 형식으로 이전되고 예전 키는 삭제된다.
