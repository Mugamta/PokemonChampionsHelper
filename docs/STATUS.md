### 상대 HP % 는 버림 표시로 확정 (2026-10-24, 사용자 요청)

- 게임의 HP % 는 버림 → p% = 실제 [p%, (p+1)%) (`utils/hpDisplay.ts`). 예전엔 표시 규칙을 몰라 (p−1)%~(p+1)% 로 넓게 잡던 것을 좁힘:
  상대 HP 실수치 범위(`oppHpRange`), 준 데미지 추정(`dealtMatches` — 전/후 화면 % 로 가능한 실제 데미지 범위, ±1%p 허용 삭제), 흡수 관측, 계산용 실수치(범위의 가운데)
- 턴 끝 정수 % 맞춤: 턴 시작에 가득 차 있고 화면 % 를 입력하지 않은 상대는 버림 (100% → 모래바람 → 예전 95%/94% 반올림 → 버림). 나머지는 반올림(= 실제 p+0.5 를 버림)
- 추정 최대 HP 가 실제와 다르면 턴 끝 데미지 결과가 1% 어긋날 수 있음 (38% → 모래바람: 최대 HP 151 이면 32%, 실제가 142 면 33%)
- 턴 끝 HP 관측: 턴 끝 HP(모래바람·먹다남은음식·상태이상 등)를 게임 화면 값으로 고치면 그 결과가 나올 수 있는 HP 실능치만 남김
  (`utils/hpDisplay.hpStepsMatch`, `MonState.hpCheck`/`hpObs`, 추정 패널 내구 관측 수에 포함, 상대 HP 입력칸에 안내 툴팁). 2%p 넘게 고치면 다른 입력을 고친 것으로 보고 무시
- 아직: 행동 칸 "체력 전후"의 "맞기 전 HP"를 지금 HP 와 다르게 입력해도 그건 관측으로 쓰지 않음 (상대 HP 칸을 고쳐야 함)
- 테스트 369개
- 배틀 패널 실능치 아래에 능력 포인트 (+X): 내 쪽은 입력값, 상대는 추정 실능치 범위에 들어가는 SP 범위 (`statInference.spRangeOf`, 성격 보정을 모르면 하락~보정 모두라 넓게 나옴), 변신 중이면 표시 안 함
- 테스트 370개

### 기술 사용률 · 앙코르 · 확정 기술과 PP (2026-10-24, 사용자 요청)

- 상대 기술 선택: 확정(이번 배틀에서 쓴 기술) → 후보(상대 파티에 적은 기술 + 사용률 높은 순) → 그 외(이름순) 로 묶고 사용률 % 표시 (`ActionPanel.moveGroups`, usage.json `moveUsage`)
- 앙코르: 마지막으로 쓴 기술을 알면 행동 칸 기술을 그 기술로 고정(선택 막음 + 안내), 턴 적용 때도 맞춤 (`useBattle.encoreMove`). 마지막 기술을 모르면 고정 안 함
- PP: 기술을 쓰면 `MonState.ppUsed` 에 기록 (빗나가도 1, 상대를 노리는 기술은 노린 상대 중 프레셔마다 +1, 설치기는 필드의 상대 모두, 교체해도 유지, 잠듦으로 못 쓰면 0).
  포켓몬 패널에 기술별 남은 PP — 내 쪽은 정해둔 기술, 상대는 쓴 기술(확정) + 모르는 칸 ?
- 잠꼬대·흉내내기: 행동 칸에서 "나간 기술"을 따로 고름 (`ActionState.via` = 부른 기술, `move` = 나간 기술). 데미지·효과·예상은 나간 기술로,
  PP·잠듦 판정·우선도·앙코르(lastMove)는 부른 기술 기준. 상대가 잠꼬대로 낸 기술은 확정(`movesSeen`), 흉내내기 선택지 맨 위는 직전에 나간 기술(`lastUsedMove`).
  손가락흔들기는 챔피언스에 없음
- 변신: 복사한 기술은 PP 5 를 따로 씀 (`tfPpUsed`, 변신이 풀리면 지움). 원한(−4)·으스스주문(맞히면 −3)으로 대상의 마지막 기술 PP 감소,
  과사열매는 PP 가 0 이 되면 10 회복(최대 PP 까지)하고 소모
- 앙코르 남은 턴 표시 (이번 턴 포함, `encoreTurnsLeft`)
- 테스트 377개

2. **입력이 필요한 효과**: 부가효과는 확률만 표시하고 실제로 걸렸는지는 "이번 턴 상태이상 발생"으로 입력, 변덕쟁이 랭크 변화도 직접 입력
   (게임 결과를 봐야 알 수 있음).
3. **테스트 범위**: 화면 컴포넌트는 자동 테스트 없음 (Playwright 스크린샷으로 확인). 스피드 구간·배분 추정은 단위 테스트 + 배틀 테스트 몇 개.
4. **모바일**: 에뮬레이션으로만 확인. 실제 휴대폰에서 써 보고 불편한 점 확인 필요. 선출 화면은 내 파티 6장 아래에 표가 있어 스크롤이 길다.

## 다음 세션 시작 방법

```bash
git checkout main
npm install          # vitest 설치 때 npm 10.9 버그로 --legacy-peer-deps 를 썼음. 일반 install 은 정상
npm test             # 계산 엔진 (@smogon/calc 대조) + 배틀 진행
npm run lint         # ESLint (TS / Vue)
npm run dev          # http://localhost:3000
node scripts/verify-data.mjs --dex   # 데이터 검증 (scripts/.cache/serebii 캐시 사용)
```

주의:
- Windows Git Bash 에서 `NUXT_APP_BASE_URL=/PokemonChampionsHelper/` 를 줄 때는 `MSYS_NO_PATHCONV=1` 필수 (안 하면 모든 HTML 이 "Redirecting...").
- `npx nuxt dev` 를 백그라운드로 띄웠다가 셸만 종료하면 `nuxi dev` node 프로세스가 남아 포트/락을 잡는다 → 프로세스를 직접 종료.
- composable 의 타입만 `import type` 하면 같은 모듈 함수 자동 import 가 빠진다 → 함수도 명시적으로 import ([CLAUDE.md](../CLAUDE.md) 6번).
- 새 composable 파일을 추가하면 dev 서버가 자동 import 를 늦게 반영하는 경우가 있다.
- 게임 데이터는 `public/data` 를 직접 고치지 말고 `scripts/sources/` 수정 → `npm run build:data` → `node scripts/verify-data.mjs`.
